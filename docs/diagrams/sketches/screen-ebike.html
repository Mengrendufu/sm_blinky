sm_blinky · 画面布局 v3 —— 照 LVGL e-bike demo 改造

参照 lvgl/lv_demos · src/ebike/（本地 3rd_party/lvgl/demos/ 里没有，联网取的原码）：它的 home 页是 左=大环（lv_arc 660×660、弧宽 20、knob 透明）+ 环心大数字（两个 roller + font_ebike_130）+ 刻度（9 个 obj 靠 transform_rotation 旋转）， 右=电池条（lv_bar）+ 里程卡（圆角 12、turquoise 底、大/小 label），另有顶栏 3 个图标、页面点 bullets、Lottie 动画。
本版改造：保留结构，按 240×320 纵向重排（环在上、卡片在下 —— demo 自己的纵向分支也是这么排的）；配色沿用 demo 的 EBIKE_COLOR_TURQUOISE 0x55FFEB / LIME 0x91FF3B。blinky 缩成顶栏一个 8×8 状态灯。

这一版推翻了我上一版的悲观估算：我原来按"弧动画要重绘整个 160×160"算（34.8 ms ✗），实测读源码发现 lv_arc 只有在角度增量 >180° 时才整块失效（lv_arc.c:175），平滑动画走的是 lv_obj_invalidate_area() 只失效变化扇区（lv_arc.c:900）→ 每帧只有几十像素。
结论：e-bike 那种大环 + 大数字的观感，在这颗片子 240×320 上是能连续动画的（弧扇区 + 大数字 + 进度条同时动 ≈ 5.7 ms ≈ 17%）。 唯一禁区是"跳变 >180°"和整屏动画。
