方案 A（推荐）— 页 2 保持今天的 blinky demo：

· 节拍环（七步/边沿，≈7 s 一圈）
· 卡：edges + frame NN.N ms
· 底栏条：帧时预算
· 页点

好处：帧时读数留在板上；两页分工清楚（系统 / blinky）。

方案 B：页 2 继续堆诊断（帧时 min/max、池、栈按线程）— 会和页 1 的清单重复。
① led 保留在右上角（跟板载同步闪）；原来的 cpu NN% 文本取消，数值进弧里。
② cpu 用半圆 lv_arc：bbox 156x78 ⇒ 整行带 3 条 ≈ 10 ms/次，2 Hz ⇒ 占用 ~2%。
③ 清单每行 = 条 + 百分比 + 数字（mockup 原话）；这里示例 5 行：三个线程栈 + tracer nmin + 事件池空闲。
④ 页点保留（两页指示）。
三、数据来源（都能拿到，且都便宜）
显示来源成本 / 备注
cpu 半圆弧 + 弧内 %BSP_cpuSample() 差分（已有 ✓） 2 Hz 刷一次；弧 bbox 156x78 ⇒ 整行带 3 条 ≈ 10 ms/次 ⇒ 占用 ~2% ✓
各线程栈占用（每行一条） uxTaskGetSystemState() + usStackHighWaterMark； 本内核 configUSE_TRACE_FACILITY=1 已开 ✓ 一次调用给全部任务（名字 + 水位）；任务有 ui / flash / blinky / Tmr Svc / IDLE ⇒ 建议按占用排序取前 3~4 行，其余折成一行
注意：水位是历史峰值（只升不降）✓
tracer nminSM_Tracer_inst.nMin / nTot(=16) 一个字节读；0 = 泵落后到丢记录 ⇒ 那一条建议变红/黄
事件池空闲块 待接：SST 静态事件池（ports/sst_port.h: SST_EVT_POOL_NUM 1）需要一个 free 读数； 另有一个候选是 UI inbox（ui_evt.c: UI_INBOX_LEN 16 + Ui_used_，现成 ✓） 一个计数读；接到后 1 行搞定
弧里那个数字用 默认字体（14 px）：放大曾被否 （lv_transform 会走 layer 路径、要 ARGB8888，本构建关掉了）⇒ 真要大字号得做一份字体，不是一行代码的事。
