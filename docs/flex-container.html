2. 主轴 / 交叉轴 / 轨道




子项沿主轴排列;启用 *_WRAP 后,
排不下才换出新的轨道(track);
轨道沿交叉轴堆叠。
ROW 时:主轴水平、交叉轴竖直、一条轨道就是一行;
COLUMN 时完全对调:主轴竖直、交叉轴水平、一轨一列。


容易记错的一点:
crossPlace 只负责子项在自己那条轨道内
的对齐(ROW 轨道高 = 该轨最高子项;
COLUMN 则是轨道宽 = 最宽子项,都不是整个内容区);
trackPlace 才负责整条轨道在容器交叉轴上的位置——
哪怕只有一条轨道,trackPlace 也能把它推到中间或底部。
想上下居中一整排,改 trackPlace,不是 crossPlace。


间隙映射:padColumn 是水平间隔,
padRow 是竖直间隔。ROW 时子项间 = padColumn、
轨道间 = padRow;COLUMN 时子项间 = padRow、轨道间 =
padColumn。四个边 pad 只收缩内容盒,
外框尺寸不变。图上珊瑚色表示最终子项间隔;
SPACE_BETWEEN 时标签拆成 配置间距 + 额外分配,
轨道间隔同理标出。

5. 事实与示意口径




事实
助手只创建一个普通、透明、去样式、被动的子对象;
它按配置设定尺寸、flow、三种对齐与六个 pad;
它不定位对象、不创建屏幕,
parent 与 config 非空是硬性要求(SM_REQUIRE),
config 只在调用期借用、不保留;
不额外创建像素缓冲,LVGL 对象与样式仍需分配内存;
未写的字段由调用方用指定初始化补零。


示意
上图是教学几何推演:正像素固定尺寸、
从左到右、无边框/外边距/grow/reverse/scroll/字体排版;
不是浏览器 CSS flex,也不是 LVGL 渲染器,
不支持的对齐模式已排除;不保证与 LVGL 逐像素一致
(舍入也可能不同),更不是 MCU 上的实测或周期数据,
与 Figma 无关。溢出时只画虚线警示,不模拟 LVGL 的
裁剪细节。
